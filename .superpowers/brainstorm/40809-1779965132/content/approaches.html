Architecture Approaches

Three ways to build it — same MathLive core, different levels of control

A
Custom React Toolbar + MathLive math-field ★ Recommended
Build a fully custom React toolbar (tabs + symbol grid) that drives a <math-field> web component. You own 100% of the UI, MathLive owns 100% of the math input engine.

Pros

  • Pixel-perfect MathType layout
  • Full control over every pixel
  • Symbol data as clean JSON config
  • MathLive handles all math input complexity
  • Easiest to extend / restyle

Cons

  • Need to define symbol JSON for all 10 tabs
  • ~3–4 days to build properly
B
MathLive Virtual Keyboard Customized Simpler
Use MathLive's built-in virtual keyboard system, customized with keylayouts that mimic MathType tabs. Less custom code — MathLive drives the toolbar too.

Pros

  • Less custom code to write
  • MathLive keylayout JSON is well-documented
  • Faster to prototype

Cons

  • VK is mobile-first, harder to style for desktop
  • Less visual control — hard to match MathType exactly
  • Fighting MathLive's defaults constantly
C
Full Custom (MathLive + KaTeX preview + Custom everything) Overkill
Build the toolbar, the math renderer, the cursor logic all from scratch. Use MathLive only for LaTeX parsing. Full control but massive scope.

Pros

  • Ultimate control over every behavior

Cons

  • 3–6 months to build well
  • Reinventing what MathLive already solved
  • High maintenance burden
  • Not worth it — MathLive is excellent
